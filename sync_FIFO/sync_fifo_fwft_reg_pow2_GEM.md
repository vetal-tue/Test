Этот вариант спроектирован так, чтобы **интегрироваться в блочную память (Block RAM)** современных FPGA (Xilinx, Intel/Altera), поскольку чтение памяти синхронизировано и заведено на выходной регистр `rd_data`. При этом мы избегаем лишних задержек ( bubbles ) благодаря схеме обхода (bypass) RAM, когда FIFO пустое или когда в нем находится ровно один элемент.

### Особенности архитектуры:

1. **Точный объем**: Максимальная емкость FIFO составляет ровно 2^ADDR_W слов.

2. **Экономия ресурсов**: Поскольку 1 слово всегда буферизируется в выходном регистре `rd_data`, в самой RAM хранится максимум 2^ADDR_W-1 слов. Это позволяет делать адресацию указателей `wr_ptr` и `rd_ptr` шириной ровно в `ADDR_W` бит без необходимости в дополнительном старшем бите для отслеживания переполнения RAM. Разница указателей всегда однозначна!

3. **Bypass-логика**: Если FIFO пусто, новые данные защелкиваются напрямую в `rd_data` за 1 такт в обход RAM. То же самое происходит при одновременном чтении и записи, когда в FIFO оставался всего один элемент.

### Код модуля на Verilog

```verilog
module sync_fifo_fwft_reg_pow2_GEM #(
    parameter DATA_W = 16,
    parameter ADDR_W = 3,
    parameter ALMOST_FULL_THRESH = (1 << ADDR_W) - 1,
    parameter ALMOST_EMPTY_THRESH = 1

) (

    input                   clk,
    input                   rst,
    // write side
    input                   wr_en,
    input      [DATA_W-1:0] wr_data,
    output reg              wr_full,
    output reg              wr_almost_full,
    output reg [  ADDR_W:0] usedw,
    // read side
    input                   rd_en,
    output reg [DATA_W-1:0] rd_data,
    output reg              rd_empty,
    output reg              rd_almost_empty

);

  

  // Указатели для записи и чтения из RAM
  reg [ADDR_W-1:0] wr_ptr;
  reg [ADDR_W-1:0] rd_ptr;  

  // Двухпортовая память
  // Локальные параметры и объявление памяти

  localparam DEPTH = 1 << ADDR_W;  

  // Для Xilinx/AMD Vivado:
  (* ram_style = "block" *) reg [DATA_W-1:0] ram[0:DEPTH-1];
  
  // // Для Intel/Altera Quartus:
  // (* ramstyle = "M20K" *) reg [DATA_W-1:0] ram[0:DEPTH-1];

  
  // Сигналы успешной транзакции
  wire do_pop = rd_en && !rd_empty;  

  // Разрешаем запись, если FIFO не заполнено, ИЛИ если оно заполнено, но сейчас читается
  wire do_push = wr_en && (!wr_full || do_pop);

  // Логика обхода RAM
  wire bypass_to_rd_data = do_push && (rd_empty || (wr_ptr == rd_ptr && do_pop));
  wire load_from_ram = do_pop && (wr_ptr != rd_ptr);
  wire ram_write_en = do_push && !bypass_to_rd_data;  

  // Предвычисление следующего состояния счетчика usedw
  reg [ADDR_W:0] usedw_next;
  always @(*) begin
    case ({
      do_push, do_pop
    })

      2'b10: usedw_next = usedw + 1'b1;  // Только запись
      2'b01: usedw_next = usedw - 1'b1;  // Только чтение
      default:
      usedw_next = usedw;  // Нет транзакций или R+W одновременно
    endcase
  end  

  // Основной синхронный процесс управления
  always @(posedge clk) begin
    if (rst) begin
      wr_ptr          <= {ADDR_W{1'b0}};
      rd_ptr          <= {ADDR_W{1'b0}};
      rd_data         <= {DATA_W{1'b0}};
      rd_empty        <= 1'b1;
      wr_full         <= 1'b0;
      wr_almost_full  <= 1'b0;
      rd_almost_empty <= 1'b1;
      usedw           <= {(ADDR_W + 1) {1'b0}};
    end else begin
      // 1. Управление выходным регистром данных и указателем чтения
      if (bypass_to_rd_data) begin
        rd_data <= wr_data;
      end else if (load_from_ram) begin
        rd_data <= ram[rd_ptr];
        rd_ptr  <= rd_ptr + 1'b1;
      end  

      // 2. Запись в RAM и обновление указателя записи
      if (ram_write_en) begin
        ram[wr_ptr] <= wr_data;
        wr_ptr      <= wr_ptr + 1'b1;
      end  

      // 3. Синхронное обновление счетчика и статусных флагов
      usedw           <= usedw_next;
      rd_empty        <= (usedw_next == 0);
      wr_full         <= (usedw_next == (1 << ADDR_W));
      wr_almost_full  <= (usedw_next >= ALMOST_FULL_THRESH);
      rd_almost_empty <= (usedw_next <= ALMOST_EMPTY_THRESH);
    end
  end  

endmodule
```

### Как это работает "под капотом":

- **Синхронный сброс (`rst`)**: Очищает указатели и выставляет дефолтные значения флагов. На выходе `rd_empty` и `rd_almost_empty` выставляются в `1`.

- **Первая запись в пустое FIFO**: При `wr_en = 1` условие `bypass_to_rd_data` становится истинным. Данные `wr_data` напрямую защелкиваются в `rd_data`. На следующем такте `rd_empty` падает в `0` и данные уже доступны для чтения внешними модулями.

- **Последовательные записи**: Так как `rd_empty` равен `0`, последующие элементы через `ram_write_en` складываются в массив `ram` по адресу `wr_ptr`, а `wr_ptr` инкрементируется.

- **Чтение**: При `rd_en = 1` текущее значение в `rd_data` считается считанным, а в него параллельно загружается следующее слово из `ram[rd_ptr]`. При этом `rd_ptr` сдвигается вперед.

- **Флаги ALMOST**: Рассчитываются комбинаторно от `usedw_next` и защелкиваются на триггерах без внесения дополнительного такта задержки, обеспечивая отличный тайминг для критических путей автомата управления (FSM) твоего проекта.

## Логика обхода (Bypass Mux)

Поскольку это FWFT-архитектура, у нас есть условие `bypass_to_rd_data` (когда данные пишутся напрямую в выходной регистр в обход памяти). Синтезатор сделает следующее:

1. Выделит чистый массив под `ram` (внутри BRAM).
2. Вынесет мультиплексор обхода во внешнюю логику (LUTs) на кристалле, которая будет стоять прямо перед триггером `rd_data`. Это абсолютно стандартная практика для FWFT-буферов, работающая без каких-либо проблем.
## Особенности реализации:

1. **Идеальный тайминг (Максимальная частота / Fmax):**    
Так как порты выходят напрямую с выходов триггеров (Flip-Flops), путь от FIFO до следующего модуля (или физической ножки плис) не содержит комбинаторной логики. Это минимизирует задержки распространения сигнала ($T_{co}$ — Clock-to-Output delay) и критически важно для успешного прохождения Timing Closure (анализа временных задержек) на высоких частотах (200–400+ МГц).

2. **Никаких глитчей (Помех):**
Если бы использовались чисто комбинаторные флаги через `assign` (например, `assign rd_empty = (usedw == 0)`), то во время изменения счетчика `usedw` на линии `rd_empty` могли бы возникать наносекундные ложные импульсы (глитчи) из-за разной скорости прохождения сигналов по разным цепям сумматора. Благодаря регистровому выходу, все флаги переключаются строго синхронно с фронтом `clk` и физически не могут глитчевать.

3. **Синхронность «на лету» без задержки в такт:**
Внимание на то, как рассчитываются флаги. Вместо того чтобы брать уже защелкнутое значение `usedw` и сравнивать его (что привело бы к опозданию флагов на 1 такт), схема берет **комбинаторное предвычисленное** значение `usedw_next` и защелкивает результат сравнения в триггеры флагов в тот же самый такт. 
_То есть: флаги отражают реальное состояние FIFO "прямо сейчас", но при этом сами физически являются регистровыми._ 

---
# bypass_to_rd_data = do_push && (rd_empty || (wr_ptr == rd_ptr && do_pop));

Этот фрагмент кода —  решение одной из самых тонких проблем в FWFT (First-Word Fall-Through) FIFO.

Если перевести эту строчку на человеческий язык, условие `(wr_ptr == rd_ptr && do_pop)` означает следующее:

> **«В FIFO сейчас находится ровно один элемент, мы его прямо сейчас читаем, но одновременно с этим записываем новый».**

Разберем по шагам, почему это так работает и зачем это нужно.

### 1. Как распределяются данные в FIFO?

В данной архитектуре выходной регистр `rd_data` всегда хранит «первое слово на выход». Сама RAM хранит только те элементы, которые стоят в очереди _за ним_.

Отсюда логика:

- Если в FIFO **0 элементов** (пусто): RAM пуста, `rd_data` пуст.    
- Если в FIFO **1 элемент**: этот единственный элемент находится в регистре `rd_data`. Сама RAM при этом **пуста**.    
- Если в FIFO **2 элемента**: один в `rd_data`, второй — в RAM по адресу `rd_ptr`.

### 2. Что означает `wr_ptr == rd_ptr`?

Равенство указателей RAM всегда означает, что **сама память RAM пуста** (в ней нет данных, ожидающих очереди).

Но при этом само FIFO не обязательно пустое! Если в FIFO есть ровно 1 элемент, он лежит в `rd_data`, а RAM пустует. В этот момент:

- `rd_empty` равен `0` (FIFO не пустое, в нем есть 1 элемент).    
- `wr_ptr == rd_ptr` равен `1` (память RAM пуста).    

### 3. Сценарий: Чтение + Запись при 1 элементе в FIFO

Представим ситуацию на такте:

1. В FIFO лежит всего **один элемент** (например, число `8` в регистре `rd_data`).    
2. Внешний читатель выставляет `rd_en = 1` (хочет забрать это число `8`). Значит, `do_pop` становится равен `1`.    
3. В этот же самый момент внешний писатель подает новые данные (например, число `99`) и выставляет `wr_en = 1`. Значит, `do_push` тоже равен `1`.    

**Что должно произойти по логике FWFT?**

- Число `8` успешно считывается.    
- FIFO не должно стать пустым, ведь мы только что записали `99`. Более того, по правилам FWFT это число `99` должно **мгновенно** (на следующем такте) появиться в регистре `rd_data`.    
- Но откуда его взять? Память RAM пуста (`wr_ptr == rd_ptr`), из нее ничего нельзя вычитать в `rd_data`.    

Вот тут и срабатывает условие:
```verilog
bypass_to_rd_data = do_push && ( ... || (wr_ptr == rd_ptr && do_pop) );
```

Оно видит: мы пишем (`do_push`), RAM пуста (`wr_ptr == rd_ptr`), и мы забираем последний элемент (`do_pop`).

Схема понимает, что новое значение `99` нужно отправить **в обход RAM напрямую в регистр `rd_data`**.

На следующем такте число `99` оказывается в `rd_data`, а FIFO остается в состоянии «содержит 1 элемент», минуя ненужную запись в память и последующее чтение из нее. Это исключает появление «пузырей» (лишних тактов ожидания) и экономит энергию.

# Синтез в FPGA

С точки зрения физического синтеза в кремний FPGA (будь то AMD/Xilinx Artix-7 или Intel Cyclone 10 GX), **вариант БЕЗ байпаса синтезируется легче и работает на более высокой максимальной частоте ($F_{max}$)**.

Однако вариант **С байпасом является отраслевым стандартом для FWFT FIFO**, поскольку обеспечиваемая им 100% пропускная способность без «пузырей» практически всегда перевешивает незначительные потери по частоте.

Проведем подробный инженерный анализ того, что происходит внутри кристаллов Artix-7 и Cyclone 10 GX при синтезе обоих вариантов.

## Главное структурное различие

Вся разница кроется в том, где физически будет реализован выходной регистр `rd_data`.

### Вариант БЕЗ байпаса (Классическое FIFO)

Данные из памяти поступают напрямую на выход: `rd_data <= ram[rd_ptr]`.

- **Как это синтезируется:** Современные блоки памяти в FPGA (**RAMB18/RAMB36** в Artix-7 и **M20K** в Cyclone 10 GX) — это специализированные жесткие IP-блоки (hard primitives). Внутри них, прямо на выходе кремниевой матрицы памяти, уже есть встроенные «жесткие» триггеры (выходные регистры).
- **Результат:** Синтезатор полностью упаковывает FIFO внутрь одного блока BRAM/M20K. Данным не нужно выходить в общую логическую матрицу (fabric) для фиксации. Тайминг идеален, частота максимальна (**400+ МГц**).

### Вариант С байпасом (Наше full-throughput FWFT FIFO)

Появляется логика: `rd_data <= bypass_to_rd_data ? wr_data : ram[rd_ptr]`.

- **Как это синтезируется:** Ни Artix-7, ни Cyclone 10 GX не имеют внутри своих блоков памяти встроенного мультиплексора, который мог бы подмешать данные из шины записи `wr_data` до встроенного выходного регистра.
- **Результат:** Синтезатор вынужден **отключить** встроенный жесткий регистр внутри BRAM/M20K. Вместо этого он берет сырой (незарегистрированный) выход из матрицы памяти, выводит его наружу в общую логику (LUT), строит там мультиплексор обхода и заводит результат на обычные триггеры (Flip-Flops) в логических ячейках (Slices/ALMs).

## Подробный анализ по семействам FPGA

### 1. Архитектура AMD/Xilinx Artix-7 (Slices + RAMB36E1)

Artix-7 построена на **6-входовых LUT (LUT6)** и триггерах, сгруппированных в слайсы (Slices).

```
[ RAMB36E1 (Память) ] 
       │ (Сырые данные)
       ▼
 [ LUT6 (Мультиплексор) ] <─── [ wr_data (Шина записи) ]
       │
       ▼
 [ Slice FF (Регистр rd_data) ]
```

- **Критический путь (Critical Path):** В варианте с байпасом критический путь идет по маршруту: `wr_en / wr_full` ──> Логика флагов (`do_push`) ──> Управление мультиплексором обхода ──> Вход данных триггера `rd_data`.
- **Влияние на тайминг:** Из-за того, что данные выходят из блочной памяти в логическую матрицу, проходят через LUT6 и только потом защелкиваются в Slice FF, добавляется задержка на трассировку (routing delay). На Artix-7 скорость этого пути составит примерно **250–320 МГц** (в зависимости от speed grade микросхемы), вместо потенциальных 400+ МГц.    
- **Ресурсы:** Вариант с байпасом дополнительно расходует по 1 LUT6 на каждый бит шины данных `DATA_W` для реализации мультиплексора. При `DATA_W = 16` это всего 16 LUT — незначительная плата.    

### 2. Архитектура Intel Cyclone 10 GX (ALMs + M20K)

Cyclone 10 GX — это гораздо более мощная и современная архитектура (на базе ядра Arria 10). Она использует **ALM (Adaptive Logic Modules)** с 8-входовыми фракционируемыми LUT.

- **Критический путь:** Архитектура блоков M20K в Intel жестко требует синхронного чтения. Наличие байпаса заставляет Quartus выносить регистр `rd_data` в ALM.    
- **Преимущество Cyclone 10 GX:** Архитектура ALM за счет своей адаптивности и наличия глубоких предвычисленных цепочек переносов может упаковать логику управления (`bypass_to_rd_data`) и сам мультиплексор данных в один и тот же физический ALM-слой. Потери по частоте здесь будут меньше, чем в Artix-7. Схема с байпасом легко заведется на частотах **350+ МГц**.    
- **Особенность мелких FIFO:** Если глубина FIFO мала (`ADDR_W = 4`), Quartus может вообще отказаться от использования блоков M20K и полностью собрать FIFO на **MLAB (LUTRAM)**. В случае с MLAB вариант с байпасом практически не имеет штрафов по скорости, так как MLAB изначально работает в логической матрице.

## Инженерный вердикт

1. **Использовать с байпасом, если:** Проектирутся интерфейсные модули (например, обвязку для AXI-Stream, PCIe, Ethernet, или стыкуются разные блоки процессора). В этих сценариях логика "пузырей" и ожидания данных убьет всю производительность системы. Потеря 50 МГц максимальной частоты полностью компенсируется идеальным поведением шины данных.

2. **Убирать байпас, если:** цель — выжать **абсолютный максимум по частоте** (например, FIFO стоит внутри конвейера цифровой обработки сигналов DSP, работающего на частоте 450 МГц), а логика вокруг FIFO готова к тому, что после появления сигнала «не пусто» данные будут идти с задержкой в пару тактов.
